# Recall · 记忆助手 — 云端多用户与小程序方案（设计稿 v4）

> 2026-08-18 v4。产品形态定为**双渠道**：
> 1. **GitHub 开源版**：懂技术的用户下载后在自己电脑上运行（即现在的本地版，原样保留）；
> 2. **微信小程序版**：手机背题的用户直接使用（新建）。
>
> 约束不变：① LLM 费用不由作者承担（BYOK + 免费模型兜底）；
> ② 用户 Key 不泄露不上传；③ 不做社区/公开发布。
>
> v4 变更：明确双渠道定位；前端策略定为"一个后端内核、两个前端"（PC 前端不动，
> 新增 uni-app 移动端）；判分路径对比细化（下沉 vs 转发）。

## 1. 总体结论

**不推翻，只增加。** 现有代码是一个完整的"单用户内核"，演进是套两层外壳：

```
┌─────────────┐   ┌─────────────┐
│ GitHub 本地版│   │ 微信小程序版 │
│ PC Vue 前端  │   │ uni-app 前端 │（新建，移动端布局）
│ (原样保留)   │   │             │
└──────┬──────┘   └──────┬──────┘
       │ localhost        │ wx.cloud.callContainer
       ▼                  ▼
┌──────────────────────────────┐
│  FastAPI 内核（agents/llm/题库）│ ← 同一套代码
│  本地：SQLite + .env          │
│  云端：PostgreSQL + user_id    │
└──────────────────────────────┘
```

- **原样保留（约 80%+）**：6 个 Agent、题库清洗管线、LLM Provider 封装、
  数据模型、PC 前端全部页面。
- **少量修改**：数据模型加 `user_id` 维度（业务数据 + 题目归属）。
- **新增**：微信登录、Docker/云托管部署、uni-app 移动端前端、题库双层结构。

## 2. 前端策略：一个内核、两个前端（回答"前端是否重构"）

不做响应式硬改，**新增独立的移动端前端**，PC 前端一行不动：

| | GitHub 版（现有） | 小程序版（新建） |
|---|---|---|
| 技术 | Vue 3 SPA（现状） | uni-app（Vue 3） |
| 复用 | — | API 层、状态管理、交互流程、视觉语言（纸白/墨色/宋体/手绘 SVG） |
| 布局差异 | 顶部导航、宽幅弹窗、左右对照 | 底部 Tab、全屏卡片、纵向堆叠 |
| 交互差异 | 右键存笔记、划句选词、悬停 | 长按、点按、系统分享 |
| 需重写的点 | — | canvas 背诵卡片导出（小程序 canvas API）、划句选词（小程序无原生 selection，改为长按复制或整段引用）、右键菜单（改长按菜单） |

## 3. 判分路径：下沉 vs 转发（回答"两者区别"）

| | ① 判分下沉到小程序（目标态） | ② 服务器转发（过渡态） |
|---|---|---|
| 流程 | 小程序拼判分 prompt → 直连 DeepSeek（用户 Key）→ 本地解析分数 → 分数 POST 回服务器存档 | 小程序把答案+Key（请求头）发给服务器 → 服务器跑 grader → 返回分数，Key 即用即弃 |
| Key 是否经过服务器 | **不经过，不出手机** | 经过（不落库，但客观流过） |
| 后端改动 | grader 的 prompt/解析/反背诵字符比对移植为 JS（约 200 行，纯搬运） | 零改动 |
| 服务器负载 | 零 LLM 流量 | 全部 LLM 流量中转 |
| prompt 迭代速度 | 改一次要发小程序审核（数天） | 服务端改完立即生效 |
| 隐私叙事 | 完美 | 需隐私政策明示"转发不存储" |
| 分数篡改 | 理论可行（客户端可改），背诵工具骗自己无意义，接受 | 无 |

**决策建议：M2 先用 ② 快速上线，紧接着做 ①。** ① 的移植工作量小，
而"Key 不出手机"是对用户最硬的承诺。

## 4. API 费用与题库

- **BYOK**：用户在小程序设置页填自己的 DeepSeek Key，只存本地 storage（见第 3 节）。
- **免费模型兜底**：智谱 GLM-4-Flash 免费档（以官网为准），没 Key 也能体验。
- **题库双层结构**：
  - 官方题库（现有 174 题及更新）：作者维护，全员只读；
  - 用户私有题库：用户用同一录入管线（粘贴文本 / md / txt / json / pdf）上传，
    仅自己可见；训练/图谱/统计在"官方 ∪ 私有"并集上进行；
    导入的 LLM 消耗走用户自己的 Key；导入去重只与其可见题集比对。
  - 若未来做"分享题库给他人"，性质变为 UGC，需重新评估资质——本方案明确不做。

## 5. 复用 vs 新增清单

| 模块 | 处置 | 说明 |
|---|---|---|
| agents/ 出题·评分·策略·导入 | 保留 | 目标态下评分/变体调用移到小程序端，prompt 与解析原样搬 |
| llm/ Provider 封装 | 保留 + 加智谱 | 新注册一个 ZhipuClient |
| 题库数据 174 题 | 保留 | 云端官方公共题库；私有题走同一录入管线 |
| SQLite → PostgreSQL | 修改（仅云端） | SQLModel 换连接串；业务表加 `user_id`。本地版继续 SQLite 不变 |
| PC 前端 | 原样保留 | GitHub 版交付物 |
| 移动端前端 | 新增 | uni-app（Vue 3），见第 2 节 |
| 微信登录 | 新增 | `wx.login` 换 openid 即账号 |

## 6. 数据模型变更（仅云端）

```
users  : id, openid(唯一), nickname, created_at
现有业务表全部加 user_id 外键 → records / sessions / notes / retry_queue /
        daily_stats / llm_usage / chat_sessions / chat_messages / question_focus
questions : 加 user_id（NULL=官方题库全员可见；否则=该用户私有题）
            读取统一 WHERE user_id IS NULL OR user_id = :me
```

本地版（GitHub）保持单用户、无 user_id，schema 差异通过迁移脚本处理。

## 7. 合规清单

1. **主体**：个人主体小程序即可（工具类目；内容仅自己可见，非公开发布）。
2. **内容安全**：无公开发布场景，不需要接内容安全审核。
3. **隐私协议**：披露 Key 仅存用户本地（① 模式）/ 转发不存储（② 过渡期）；
   openid 获取；私有题库仅本人可见可删除。
4. **GitHub 开源**：仓库加 LICENSE（建议 MIT）；`.env` 已在 .gitignore，
   README 已有 Key 红线说明。
